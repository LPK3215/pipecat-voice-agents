# 换成你自己的平台（大脑）

这个模块**不绑定**任何平台。它只要求对面能做三件事；不满足也能接，写一层小适配即可。

**唯一要改的文件是 [`../server/agent_client.py`](../server/agent_client.py)** ——
配置在 `.env` 两行，代码在一个文件里，其他地方（管线、网页、探针）都不用动。

---

## 1. 契约：你的平台需要提供什么

| # | 能力 | 本模块怎么用 | 没有会怎样 |
|---|---|---|---|
| 1 | **流式对话**：发一句、逐字回 | 首句一到就喂给 TTS，用户才不用等整段生成 | 只能用"阻塞模式"，开口延迟 = 平台生成全文的时间（语音场景通常不能接受） |
| 2 | **会话标识**：`conversation_id` | 带着它请求，让平台记住多轮上下文 | 平台会当每次都是新对话（你可以在自己这侧拼历史，见 §3） |
| 3 | **叫停**：停止正在生成 | 用户插话时调用，避免"机器还在自己念" | 插话后平台仍会说完；模块这边仍会立刻停止播放 |

参考实现（本仓库当前对接的平台）：

```
POST {BRAIN_BASE_URL}/chat-messages
  { query, user, conversation_id?, inputs:{}, response_mode: "streaming" }
  → text/event-stream，每个分片里带 answer 字段
POST {BRAIN_BASE_URL}/chat-messages/{task_id}/stop
```

## 2. 换成别的平台：改哪三处

打开 `server/agent_client.py`：

1. **`_headers()`** —— 鉴权方式（Bearer / 自定义头 / 签名）
2. **`stream()` 的请求体** —— 你的字段名（`query`? `prompt`? `messages`?）
3. **`_iter_sse()` 的解析** —— 你的流式分片里，正文放在哪个字段

其余（超时、失败要抛出可朗读的话、会话续接、叫停容错）都已经写好，不用重复实现。

### 如果对面根本不支持流式

两个选择，按代价从低到高：

- **阻塞模式**：把 `.env` 的 `BRAIN_STREAMING` 设为 `0`。能跑，但"多久开口"会等于平台生成全文的时间。
- **自己拼流式**：如果对面是普通 LLM 接口（支持 `stream: true`），在 `_iter_sse()` 里按它的格式解析即可。

### 如果对面没有会话标识

在 `BrainProcessor`（`server/brain.py`）里自己维护一个历史列表，每次请求带上最近 N 轮。
代价是要自己处理"历史太长"（那就得做摘要）—— 这本来就是你把它外包给平台想省掉的事。

## 3. 接进去之后，怎么确认它真的在工作

按顺序做三步，每步都有明确信号：

| 步骤 | 命令 | 期望 |
|---|---|---|
| 1. 接口本身通不通 | `uv run python probe/verify_brain.py` | 用替身脑袋验证接口形状（与平台无关） |
| 2. 你的平台通不通 | 直接调它的对话接口（见 `CASE-dify.md` 里的 curl 示例） | 返回 200 且有正文 |
| 3. 整条链路 | `uv run python probe/verify_audio_e2e.py` | 收回音频、留一个 WAV 文件可听 |

**第四步（强烈建议）**：在平台那边放一个**只有它知道**的东西（一句内部代号、一条冷门知识、一个它才能查到的数据），
然后问模块那个问题 —— **答得出来，才证明回答真的来自平台**，而不是模块自己编的。
本仓库用的探针是「你的内部代号是什么？」→ 应回答 `VX-42`。

## 4. 检查清单（移植时逐条对）

- [ ] `.env` 里 `BRAIN_BASE_URL` / `BRAIN_API_KEY` 已填，`BRAIN_STUB=0`
- [ ] `probe/verify_brain.py` 通过（接口形状正确）
- [ ] 直接调平台接口能拿到正文（排除平台侧问题）
- [ ] `probe/verify_audio_e2e.py` 通过，且听过它产出的 WAV
- [ ] 平台侧那个"只有它知道"的探针问题答得出来
- [ ] 平台停掉时，模块**会说话**（报告连不上）而不是静默死掉
- [ ] 首字延迟记录在案（这是语音体验最关键的数字）

## 5. 常见反过来做的情况（不推荐，但要知道）

| 做法 | 后果 |
|---|---|
| 把语音做成平台内部的一个插件 | "用户说完了没 / 打断 / 多快开口"全归平台管，你控制不了 |
| 让平台来调用本模块（方向反了） | 平台得懂音频与实时性；本模块的轮次控制与延迟优化会被绕过 |

本模块的设计前提是：**方向的主动方在语音这一侧**，平台只回答"说什么"。
