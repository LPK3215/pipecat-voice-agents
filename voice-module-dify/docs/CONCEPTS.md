# 设计说明与答疑：这个工具到底是谁在干什么

> **本文管什么**：心智模型 —— 谁在干什么、方向是哪边、常见误解在哪、为什么这样设计，以及 9 条实际问过的答疑。
> **本文不管什么**：怎么把它跑起来（见 [`../CASE-dify.md`](../CASE-dify.md)）；换成你自己的平台怎么改（见 [`PORTING.md`](PORTING.md)）。
> **适合谁看**：想先搞清"这到底是什么东西"的人 —— **建议第一篇就读它**，否则容易把方向搞反。

这份文档记录的是**心智模型**——为什么这样设计、常见的误解在哪、以及每个结论的验证方式。
技术细节在 [`../CASE-dify.md`](../CASE-dify.md) 与 [`HANDBOOK-03.md`](HANDBOOK-03.md)；
这里只回答"到底谁在干什么"，并且**每条结论都注明是怎么验证的**。

---

## 1. 一句话

> **语音模块只负责"输入和输出"。至于"怎么思考"，它调用的是外部的一个东西；那个东西是什么，它不管。**

现在那个"东西"是一个自托管的智能体平台（Dify）。**换掉它，语音模块一行代码都不用改。**

## 2. 谁是主人：方向只有一个

```
网页（你的）  ──WebSocket──▶  语音模块（你的）  ──HTTP──▶  平台（别人的服务）
```

- **语音模块是主人**：它决定什么时候去问、要不要打断、什么时候开口。
- **平台是被调用方**：它不知道网页的存在，只知道"有个客户端来问了个问题"。

### 两个常见误解（都被实验推翻）

| 误解 | 为什么错 |
|---|---|
| "平台里装了语音模块" | 把平台停掉，**网页照样打开、模块照样在听、照样出声**，只是没人回答了 → 说明模块不在平台里面 |
| "是平台调用了语音模块" | **方向反了**。是模块主动去调平台；平台从不知道网页存在 |

## 3. 责任表：谁负责什么、属于谁、换平台要改什么

| 环节 | 谁负责 | 属于谁 | 换平台时要改吗 |
|---|---|---|---|
| 收麦克风、放声音（网页） | 网页 | **你的** | ❌ 不用 |
| 判断用户说完没有（VAD + 端点检测） | 语音模块 | **你的** | ❌ 不用 |
| 语音 ↔ 文字（STT / TTS） | 语音模块 | **你的** | ❌ 不用 |
| 打断、填场、首句就开口 | 语音模块 | **你的** | ❌ 不用 |
| **回答什么、记得什么、查什么** | **平台** | **别人的** | ✅ 只改 `.env` 两行 |
| 应用、提示词、模型 key、工具、知识库 | 平台 | **别人的** | ✅ 在新平台上重配 |

### 3.1 想改点什么 → 该动哪一层

使用中最常问的一张表（都由上面的责任划分直接推出）：

| 你想要的 | 改哪里 | 要动语音模块吗 |
|---|---|---|
| 页面好看些 / 信息多一些 / 加样式 / 改布局 | 网页 `agent/deploy/voice-client.html` | ❌ |
| 回答更聪明：换模型、挂知识库、加工具、改提示词 | **平台界面** | ❌ |
| 换个平台（或换成自己写的系统） | `.env` 两行；接口形状不同时再改 `server/agent_client.py` | ✅ 一处 |
| 打断更干脆 / 填场更快 / 多久算"说完" | `server/brain.py` + `.env` 阈值 | ✅ **这是它的本职** |
| 换通道（网页 → 电话 / 微信） | `server/ws_app.py` 或传输层 | ✅ |
| **在页面上看到"AI 正在检索 / 正在调用工具"** | 网页 + 模块加一条文本通道 | ✅ 一次性（见 Q9） |

**一条界线**：**"业务功能"不用动模块；"语音体验"和"接入形态"必须动模块。**

为什么要把界线写死：如果不写，很容易为了"不改模块"而把**该由模块负责的东西**
（打断、填场、多久算说完）塞进平台 —— 那恰好会丢掉这个模块最值钱的部分（第 5 节）。

## 4. 和另一个项目（`pipecat-quickstart`）的关系

| | 业务逻辑在哪 | 谁写的代码 |
|---|---|---|
| 那里的**阶段一** | 无（只把语音链路搭通） | 你的 |
| 那里的**阶段二** | **在你自己的代码里**（工具 / 知识库 / 记忆 / 编排） | 你的 |
| **本案例** | **在平台那边**（在界面里配） | **别人的** |

**角色是一样的**（总得有人负责"答什么、查什么、记什么"），**区别只在由谁实现**：
阶段二是自己造，本案例是把这件事**外包给一个已有的智能体系统**——
所以阶段二写的那些东西在这里**一个都用不上**，这是设计如此，不是遗漏。

## 5. 这样设计的价值

1. **能力可以在平台那边一直长**：换更强的模型、挂知识库、加工具，都在平台界面里做，
   **语音这边一行不用动**，刷新页面立刻用上新能力。
2. **扩展第三方系统的正确姿势**：不碰它的代码，只用它公开的接口。
   它升级、换版本，你的模块不受影响。
3. **控制权留在手里**：语音体验的功夫（多久判定说完、怎么打断、多快开口）全在模块这边，
   这部分**别人拿不走**。
4. **它是可替换的**：哪天想换别的平台、或者换成自己写的系统，只改 `.env` 两行。

## 6. 答疑（都是实际问过的问题）

### Q1：把那个平台删掉，我的网页还能工作吗？

**一半能。** 网页**照样打开**（它是你的文件、你的服务），模块**照样在听、照样出声**；
但你说完话**没人回答**了——模块会说一句"连不上"，**不会静默死掉**。

> 实测：停掉平台的 API 容器后 → 网页 `HTTP 200` ✓、模块 `HTTP 200` ✓、
> 说话后模块日志出现 `BrainError: brain unreachable` ✓，且它仍然发出了 3.4 秒的语音回应。

### Q2：那我的"后端"到底是谁？

| 角色 | 是谁的 |
|---|---|
| 前端（你看到的那一页） | **你的** |
| 后端——"听和说" | **你的**（语音模块） |
| 后端——"思考" | **不是你的**，是一个**被调用的外部服务** |

一句话：**你拥有"怎么听、怎么说"的全部，但不拥有"想什么"。**

### Q3：那个网页算我的还是算平台的？

**算你的。** 证据有三条，都可以自己核：

1. 文件在你的仓库里：`agent/deploy/voice-client.html`；
2. 网页里**提到平台的次数 = 0**（`grep -ci dify agent/deploy/voice-client.html`）；
3. 它连的地址是**从它自己的网址换算出来**的，指向你的语音模块，不是平台。

> 试一下就知道：删掉平台，网页**不用改一行**；换一个平台，网页**也不用改一行**。

### Q4：为什么非要一个"真"平台？我自己写个假的当脑子不行吗？

因为**真平台才有它自己独有的东西**（知识库、工具、记忆）。用一个自己写的假脑子，
它答对了也说明不了任何事——那可能是模块自己猜的。

本案例留了一个"防自欺"的探针：问它 **「你的内部代号是什么？」**，正确答案是 **`VX-42`** ——
这个名字只写在平台那个应用的提示词里，**模块自己不知道**。答得出来，才证明回答真的来自平台。

### Q5：平台不是只能在它自己的界面里用吗？

平台有**两个面**：

| 它的面 | 给谁用 | 本案例用了吗 |
|---|---|---|
| 界面 / 发布成公开网页 | 人 | ❌ 没用 |
| **服务 API**（`/v1/chat-messages` + API key） | **程序** | ✅ **用的就是这个** |

### Q6：我是不是"改动"了那个平台？

**代码一行没改** ✓。但要分清两件事：

| 做了什么 | 性质 |
|---|---|
| 替换了它的两个边车容器（反向代理 / 出网代理） | **本环境的特例**：这里 Docker 守护进程看不到工作区，靠文件挂载的容器起不来 → 换成把配置烤进镜像。换台正常机器不需要 |
| 在库里直接补了"密钥 + 发布"两条记录 | **省人工点击的权宜手段**，正式做法是在界面点两下 |

### Q7：想让它更聪明怎么办？

**去平台界面里做**：换模型、挂知识库、加工具、改提示词。
**语音这边一行不用动**，刷新网页就能听到新能力。

### Q8：为什么它看起来这么"简单"（功能不多）？

因为**它的价值不在功能多，而在控制权**：多久算说完、能不能打断、多快开口。
这些都有实测数字（见下一节）。功能是平台那边的事。

### Q9：我想在页面上看到"AI 正在干什么"（检索 / 调工具 / 日志），要改哪？

**数据已经有了，缺的只是一条通道。**

| | 现状 |
|---|---|
| 平台那边 | 它的流式返回里**本来就带**过程事件：`agent_thought`（它在想什么）、`node_started` / `node_finished`（流程每一步）、`message_file`（生成的文件）—— 对着它自己的源码核过 |
| 语音模块这边 | `server/agent_client.py` **只取正文**（只处理 `message` / `agent_message` 的 `answer`），其余事件读完就丢 |
| 网页这边 | WebSocket 上**只有音频**（`RawPCMFrameSerializer`），没有文本通道，想看也收不到 |

所以缺的是**一条通道**：适配器把过程事件多发一路 → WebSocket 加一类文本/事件消息 → 网页就能显示。
做完这一次，之后"改页面"就真的只改页面了（**排期不在这里**，见 [`HANDBOOK-03.md`](HANDBOOK-03.md) 第 5 节）。

> 对照 3.1 的表格：这是唯一一处"需要动模块、但目的是让以后不必动模块"的改动。

## 7. 证据清单（都能自己复跑）

| 结论 | 怎么验证 | 实测结果（2026-10-05） |
|---|---|---|
| 回答真的来自平台 | 问"你的内部代号是什么" | 答 `VX-42`（只有平台知道） |
| 平台可替换 | 看 `.env` 的耦合面 | 只有 `BRAIN_BASE_URL` / `BRAIN_API_KEY` 两行 |
| 模块不依赖平台活着 | 停掉平台再说话 | 网页 200 ✓、模块 200 ✓、模块明确报告连不上并出声 |
| 网页不依赖平台 | `grep -ci dify` 网页文件 | 0 |
| 端到端音频可用 | `uv run python probe/verify_audio_e2e.py` | 通过：318,720 字节 / 10.0 秒音频 |
| 分段延迟 | 模块日志的 `[TURN n]` 行 | 请求发出 0ms → 平台首字 1334ms → 首句 1346ms |
| 平台自身的响应速度 | 直接调它的接口 | 首字 740–963ms（与本地模型 ~800ms 基本持平） |
| 平台会发"过程事件"（思考 / 流程 / 文件） | 读它自己的源码 | 确实有，且本模块目前只取正文 —— 字段清单与影响见 Q9 |

## 8. 有意没做 / 还没验证的

- **打断**：模块会停止并告诉平台停 ✓，但**浏览器里已排队的音频可能还会播完**（页面上有「停止」按钮兜底）。
- **合成音的识别率一般**：用机器人声音测试时"语音模块"被听成"宇英魔快"；**真人说话会好得多**。
- **平台的登录无法脚本化**（要求密码先加密、成功后走 Cookie），所以平台侧有三步必须人工 —— 见 `CASE-dify.md` 第 3 节。
- **页面上看不到"AI 在干什么"**（原因与缺什么，见 Q9）。
- **没有多租户 / 鉴权**：当前是单机单会话的形态。
