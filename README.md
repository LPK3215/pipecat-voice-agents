## The Three Projects · At a glance

### Which one do I want?

| I want to… | Go to | In one line |
|---|---|---|
| Run a **working voice agent** (listen → think → speak, all in my hands) | 📗 [`pipecat-quickstart/`](pipecat-quickstart/) | **Voice is the product itself** |
| **Plug voice into an existing agent system** (the host is the owner) | 📙 [`pipecat-open-webui/`](pipecat-open-webui/) | **Called by** an existing system |
| Make voice a **drop-in module** (the module is the owner, calling an external platform) | 📘 [`voice-module-dify/`](voice-module-dify/) | **Actively calls** the external platform |

> The most recently updated project is 📙 `pipecat-open-webui/`.
> Two more materials: 📄 [`research/pipecat-项目调研.md`](research/pipecat-项目调研.md) (**what this framework is** — read before you start) ·
> 📕 [`pipecat-quickstart/reference/pipecat-modelscope/`](pipecat-quickstart/reference/pipecat-modelscope/) (**frozen** model-selection / latency benchmarking project).

### How they actually differ

All three do "voice". They differ in exactly two questions: **who thinks?** and **where does the voice layer live?**

| | Who thinks | Where the voice layer lives | Shape |
|---|---|---|---|
| ① [`pipecat-quickstart`](pipecat-quickstart/) | Itself (LLM inside the pipeline) | Core (the pipeline itself) | **Full stack** |
| ② [`voice-module-dify`](voice-module-dify/) | An external platform (Dify, …) | A standalone service that calls the platform | **Add-on** |
| ③ [`pipecat-open-webui`](pipecat-open-webui/) | The host system (Open WebUI) | A component inside the host | **Symbiont** |

> ② and ③ point in **exactly opposite directions** — that is why they cannot replace each other, and why both exist.

## 📗 `pipecat-quickstart/` — Full Voice Agent

| Item | Description |
|---|---|
| What it is | A runnable real-time voice conversation agent; cascaded pipeline `VAD → ASR → LLM → TTS` |
| Core idea | Voice is the product itself: this pipeline owns listening, thinking and speaking end to end |
| API keys needed | **1** (only the LLM costs money; STT / TTS run fully locally) |
| Status | ✅ **Phase 2 closed (`v0.1.0`, 2026-10-05)** — capabilities, verification and docs all wrapped up |
| License | MIT |
| Stack | Python + Pipecat 1.12+; SenseVoice / Whisper (local STT) + Piper / Kokoro (local TTS) |
| Access | Browser at `http://localhost:7860/client` |

**What it deliberately owns**: the whole loop — `VAD → ASR → LLM → TTS` — plus tools, memory,
knowledge base and orchestration. *How* to build on it is not here: see `docs/HANDBOOK.md` (phase 1)
and `docs/HANDBOOK-02.md` (phase 2).

**Companion documents** — all detail lives there, this page only points at it:

| File | Content |
|---|---|
| `README.md` | How to run this project itself |
| `docs/HANDBOOK.md` | Phase 1: how it was built from scratch (slots, config, pitfalls) |
| `docs/HANDBOOK-02.md` | Phase 2: how to write your own business logic (tools, data, orchestration, test discipline) |
| `docs/TOOL_TESTS.md` | Tool-calling stress report (with **confidence annotations**; read the retraction notice at the top first) |

**Quick start**:

```bash
cd pipecat-quickstart/server
uv sync --extra sensevoice     # extra deps for the default Chinese STT (SenseVoice)
cp .env.example .env           # only MODELSCOPE_API_KEY is required
uv run bot.py                  # open http://localhost:7860/client
```

## 📘 `voice-module-dify/` — Voice Module (talks to an external platform)

| Item | Description |
|---|---|
| What it is | A **separately deployable voice module**: it only listens and speaks; thinking is delegated to an external agent system |
| Core idea | The voice layer is yours, the thinking layer belongs to the platform, connected through a **replaceable interface** |
| API keys needed | One platform key (switching platforms means editing two `.env` lines) |
| Status | ✅ **`v0.0.1` complete** (2026-10-05) — 4 probes + 33 unit tests |
| License | MIT |
| Stack | Python + Pipecat; local Whisper (STT) + Piper (TTS); WebSocket / SmallWebRTC dual entry points |
| Access | Browser at `http://localhost:8081/voice-client.html` (page served on 8081; module listens on 8090) |
| Case study | Dify (full walkthrough in `CASE-dify.md`) |

**What it deliberately owns**: the parts of voice that are genuinely hard — end-of-turn detection,
interruption, speaking while still receiving (first sentence out immediately), filling the silence while the
platform is slow, and showing thinking / tool calls / tool results / per-turn latency live on the page.
What it deliberately **does not** own: thinking, tools and memory — see `docs/CONCEPTS.md`.

**Companion documents** — all detail lives there, this page only points at it:

| File | Content |
|---|---|
| `README.md` | Project positioning and how to run it |
| `CASE-dify.md` | Full Dify walkthrough, the three steps that must be done by hand, measured pitfalls and numbers |
| `docs/CONCEPTS.md` | Mental model and Q&A (9 entries, each conclusion with a way to verify it) |
| `docs/PORTING.md` | Swap in your own platform: contract + checklist |
| `docs/HANDBOOK-03.md` | Phase handbook (how it was built; verified and unverified kept separate) |

**Quick start** (no real platform needed — a local stand-in takes its place):

```bash
cd voice-module-dify
uv sync
cp .env.example .env          # set BRAIN_STUB to 1 (local stand-in as the brain)
uv run python probe/verify_brain.py         # verify the "brain" interface
uv run python probe/verify_speech_legs.py   # verify it can really speak and listen
```

## 📙 `pipecat-open-webui/` — Voice Part (called by a host)

| Item | Description |
|---|---|
| What it is | A **fork of Open WebUI**: upgrades / completes the voice capabilities of an existing agent system |
| Core idea | The host system is the owner; voice is a **pluggable component** inside it (using its native slots, not an external service) |
| API keys needed | **1** — an OpenAI-compatible LLM key for the host's chat (`OPENAI_API_KEY`); STT runs locally, TTS runs in the browser |
| Status | ✅ **Working end to end** (LLM chat + voice I/O); experimental, not production |
| License | **Dual** — upstream code stays under the **Open WebUI License**; **files newly added on this branch are MIT** (see `LICENSE-SUPPLEMENT.md`) |
| Stack | Python / FastAPI backend + SvelteKit frontend; **UI and orchestration only, no model inference** (plain CPU is enough) |
| Access | Browser at `http://localhost:8000` (local; this branch ships no hosting — see `FAQ.md` Q12) |
| Voice implementation | **STT** = local `faster-whisper` (through Open WebUI's native slot); **TTS** = browser `speechSynthesis` |
| Upstream baseline | Open WebUI `v0.11.4` |

> **Attribution**: the "Open WebUI" branding is preserved exactly as upstream ships it — required by the Open WebUI License.

**What it deliberately owns**: only the two thin I/O edges — speech in, speech out. Thinking, tools, memory,
knowledge base and conversation management are **left entirely to the host**; that is the design, not a gap
(see `voice-docs/INTEGRATION.md` §0).

**Companion documents** — all detail lives there, this page only points at it (this branch's own docs live
in `voice-docs/`, kept separate from upstream `docs/`):

| File | Content |
|---|---|
| `README.md` | How to run this branch (source mode / addresses / `.env` configuration) |
| `voice-docs/INTEGRATION.md` | **Voice integration notes** (what was done / which files changed / which APIs were called) |
| `voice-docs/VOICE-MODES.md` | **Choosing a voice mode** (A simple I/O / B continuous conversation / C fine-grained real-time) |
| `voice-docs/VOICE-UX.md` | **Reproducing the voice UX** (auto-send / auto-read-aloud / required configuration) |
| `voice-docs/CHANGELOG.md` | **Complete record** of this branch's changes relative to upstream |
| `FAQ.md` | FAQ (including **Q14: what if speech is recognised as a foreign language**) |
| `voice-docs/PLATFORM-SELECTION.md` | Host platform survey (Open WebUI / LibreChat / LobeChat comparison) |

## Three pitfalls worth knowing

> Orientation only — one line each so you know the trap exists. The full answer lives in
> [`FAQ.md`](FAQ.md) (Q6 / Q2 / Q5) and in the project that owns it; follow the links rather than
> trusting a summary.

**1. Latency numbers are not directly comparable.**

`pipecat-quickstart` (934 ms) and `reference/pipecat-modelscope` (1.7–1.9 s) use **different baselines**:
the former measures from "the user actually finished speaking", the latter from "audio streaming ended",
which is **about 0.5 s more optimistic**.

**2. Read the retraction notice before quoting `TOOL_TESTS.md`.**

One conclusion there was overturned by repeated experiments ("the more tools, the less they get called").
The original text is kept with the reason for retraction — **do not use it as a conclusion**.

**3. Speech recognition without an explicit language = automatic language guessing.**

Whisper auto-detects when no language is given, and **in practice it misidentified Chinese as Thai**
(both ② and ③ hit this). Both projects now pin `STT_LANGUAGE=zh` / `WHISPER_LANGUAGE=zh` in `.env` —
**do not delete those two lines**.

## Language conventions (repository-wide)

**Documentation layer — two versions.**
This file (`README.md`) is the **English primary** version; the Chinese companion is
[`README.zh-CN.md`](README.zh-CN.md). Both keep an identical section structure and link to each other
at the top. Every other root-level document (`CONTRIBUTING.md`, `FAQ.md`, `CHANGELOG.md`, `AUTHORS`)
is **English-only**.

**Asset layer — one copy, always English.**
Diagrams, charts and banners (for example [`docs/repo-map.svg`](docs/repo-map.svg)) are produced **once,
in English**, with **no language suffix** in the file name. `README.md`, `README.zh-CN.md` and the
project overview page all reference the **same file at the same relative path**; the Chinese version
explains the figure in its own prose rather than forking a translated copy.

**Inside the projects**: source code, commands and terminal output are quoted verbatim (plain ASCII),
never paraphrased, so they can be copied and run directly. Prompts, tool `description` fields and spoken
lines are functional content and remain Chinese where they appear in code.
